# TongJia-Bench（通假 Bench）设计方案

> 版本：v0.1 draft ｜ 2026-09-09

## 1. 命名与定位

**TongJia-Bench（通假基准）**——"通假字"是古人有意识用同音字替代本字的现象（"学而时习之，不亦说乎"式的文化共识），恰好对应今天要测的两件事：**模型对错别字（尤其同音错字）的容错能力**，以及**对读音/拼音的理解能力**。名字自带文化梗，利于传播。

### 与现有工作的错位

| 基准 | 测什么 | 缺口 |
|---|---|---|
| READIN (2023) | 真实噪声下的任务鲁棒性 | 不区分"靠什么容错"；无拼音维度 |
| Phun-Bench (ACL 2026) | 纯语音知识运用（押韵、同音还原） | 不测容错场景；不做机制归因 |
| FiBench-CSC (COLING 2025) | 纠错任务的细粒度分类 | 测"纠错"而非"容错理解" |
| IME Bench (LREC 2026) | 拼音→汉字转换 | 无声调/混写消融 |

**TongJia-Bench 的独特卖点：不仅测"能不能容错"，还测"靠什么容错"**——这是目前没人系统做的机制归因视角，也是与所有现有基准的本质差异。

## 2. 任务体系（4 个 Track）

### T1 容错理解（Typo-Tolerant Understanding）
在下游理解任务（常识问答、句义判断、阅读理解）中注入受控错误，测性能保持率。
- **操纵变量**：错误类型（同音 / 近音[同声韵异调] / 形近 / 随机） × 错字率（0/5/10/20/30%） × 上下文长度（短句 / 段落）
- **关键要求**：错误注入使用"拟真分布"（基于拼音 IME 候选词混淆集），不用纯随机替换——向 READIN 的标准看齐

### T2 拼音剖面（Pinyin Profile）
- **任务**：拼音→汉字还原、拼音语义理解（直接回答拼音写的问题）
- **消融维度**：带调号（hǎo） / 数字调（hao3） / 无声调（hao） / 首字母缩写（zsxh） / 汉字拼音混写比例（0/25/50/75/100%）
- 这个 track 方法简单但**完全空白**，是最容易被引用的部分

### T3 机制归因（Mechanism Attribution）⭐ 核心创新
对每个同音错字样本构造三条件 minimal pair：
- **C+ 上下文强提示**：上下文明确指向目标字（"他每天早起锻练身体"→"炼"）
- **C0 上下文抽空**：上下文语义中性，不指向任何候选（"这个字写错了：锻练"）
- **C− 上下文误导**：上下文指向另一个同音字

**判定逻辑**：C0 条件下仍能恢复 → 走了"语音通道"；C0 崩溃但 C+ 成功 → 纯上下文猜测。
派生指标 **PTI（语音通道指数）** = Acc(C0) / Acc(C+)，值越高说明模型越依赖内部语音知识而非上下文。
可叠加 Phun-Bench 的"声音层"假说验证：要求模型先输出拼音再输出汉字（显式两步）vs 直接输出，比较 C0 条件差异。

### T4 同音伪装检测（Cloak Detection，可选扩展）
站在 PCR-ToxiCN / ToxiCloakCN 的矛盾结果上（拼音到底是帮手还是噪声），系统测"何时提供拼音信息有用"。有内容安全应用价值，作为 v0.2 扩展。

## 3. 评测协议

- **主指标**：各 track 的 Accuracy / EM；T1 报容错保持率 = Acc(噪声) / Acc(干净)
- **创新指标**：PTI（T3）；声调敏感度曲线（T2）
- **汇总**：Worst-group accuracy（沿 READIN 的 Worst-Average 思路），防止"平均分掩盖脆弱性"
- **参评模型建议**：≥1 推理型（DeepSeek-R1 类）+ ≥1 国际闭源（GPT/Gemini 系）+ 3-4 个开源（Qwen、GLM、Llama 系）+ 小模型基线
- **防泄漏**：T3 的干扰同音字按 Phun-Bench 的 memorization-proof 原则算法生成，确保"错字+上下文"组合在预训练语料中几乎不存在

## 4. 数据 Schema（JSONL）

```json
{
  "id": "t3-chengyu-0042",
  "track": "T3",
  "task": "homophone_recovery",
  "condition": "C0",
  "input": "这个字写错了，请改正：一劳永「遗」",
  "target": "逸",
  "meta": {
    "error_type": "homophone",
    "target_word": "一劳永逸",
    "perturbed_char": "逸",
    "distractor_char": "遗",
    "pinyin": "yi4",
    "context_condition": "neutral",
    "source": "chengyu_list_v1"
  }
}
```

## 5. 路线图

- **v0.1（pilot，本周）**：T2+T3 各 100 条，手工+脚本生成，跑 3 个模型验证现象
- **v0.2**：扩到每 track 500+ 条，T1 接入 2 个下游任务，写技术报告（arXiv）
- **v1.0**：T4、Leaderboard 页面、投稿（目标：ACL/EMNLP findings 或中文信息学会评测）

## 6. 传播策略（"炒热度"部分）

1. 名字和视觉先行：通假字的文化梗 + 一个可传播的 headline 结论（如"GPT 能背拼音但不会听音辨字"）
2. pilot 结果做成一张"模型能力剖面图"发知乎/公众号/小红书
3. arXiv 技术报告 + GitHub 开源数据与评测脚本
4. 邀请制 leaderboard：先跑 10 个模型占位
